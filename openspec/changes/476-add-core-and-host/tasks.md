## Task 2: The Node.js host package

Files: `nodejs/wishem/host-nodejs/package.json`, `nodejs/wishem/host-nodejs/README.md`, `nodejs/wishem/host-nodejs/src/index.ts`, `nodejs/wishem/host-nodejs/src/read-model-folder.ts`, `nodejs/wishem/host-nodejs/src/read-model-folder.test.ts`, `nodejs/wishem/host-nodejs/src/start-host.ts`, `nodejs/wishem/host-nodejs/src/start-host.test.ts`, `nodejs/wishem/host-nodejs/src/cli.ts`, `nodejs/wishem/host-nodejs/src/cli.test.ts`, generated config from `pnpm sync`
Interfaces: consumes `createCore`, `Core`, `ModelError`, `Problem`, `Snapshot` from `@thrashplay/wishem-core`. Produces, from `@thrashplay/wishem-host-nodejs`: `readModelFolder(folder: string): Promise<ModelFolderResult>`, `startHost(options: HostOptions): Promise<Host>`, and the `wishem` command with `wishem start <folder> [--port <number>]`. Produces the HTTP paths `GET /snapshot` and `GET /snapshots`. The exact signatures are in the "Interfaces" section of `design.md`.

- [ ] 2.1 Create `nodejs/wishem/host-nodejs/package.json` with the name `@thrashplay/wishem-host-nodejs`, a description, `"private": true`, `"type": "module"`, the standard `exports`, a dependency on `@thrashplay/wishem-core` with `workspace:*`, and `"bin": { "wishem": "./dist/cli.js" }`. Add no third-party dependency. Run `pnpm install && pnpm sync`. Verify that `pnpm build --filter @thrashplay/wishem-host-nodejs` succeeds and that `dist/cli.js` starts with a `#!/usr/bin/env node` line.
- [ ] 2.2 Implement `readModelFolder`: read each `.json` file in `definitions` and `state.json`, and give `{ definitions, entities }` as `data`. Give a problem with `source` set to the file for a missing folder, a missing `state.json`, and a file that is not valid JSON. Ignore files in `definitions` that do not end in `.json`. An absent or empty `definitions` folder gives no component types and no problem. Add a function that sets `source` on a problem from the core by its `path`: a path in `definitions` gives the definition file of that item, and a path in `entities` gives `state.json`. Verify with tests that write files to a temporary folder from `fs.mkdtemp`, for each scenario of `specs/wishem/host-nodejs/model-folder/spec.md`.
- [ ] 2.3 Implement `startHost` without the watch: read the folder, make the core, reject with `ModelError` when the model is not correct, listen on `127.0.0.1` at the port of the options, and serve `GET /snapshot`, `GET /snapshots`, status 404 for other paths, and status 405 for other methods, as `specs/wishem/host-nodejs/start-command/spec.md` requires. `close()` ends each stream and closes the port. Verify with tests that start a host on port 0 and use `fetch`: the snapshot body, the content types, the first `snapshot` event of the stream, two streams at the same time, the 404 and 405 bodies, and a rejected start for a port that is in use.
- [ ] 2.4 Add the watch: `fs.watch` on the model folder in recursive mode, a wait of 50 ms after the last event, then `readModelFolder` and `core.setModel`. Print each problem and each warning through `log`, print "the model is correct" when a correct model follows a model that was not correct, and keep the last correct snapshot. Verify with tests on a temporary folder, with a wait of 2 seconds or less for each: a changed title in `state.json` gives a new snapshot and a stream event; a changed label gives a new snapshot; a new definition file appears in the snapshot; text that is not valid JSON keeps the last snapshot and logs a problem that names `state.json`; a corrected file gives the new snapshot; a save through a temporary file and a rename gives a new snapshot. If `fs.watch` is not reliable in these tests, add a watch library to the pnpm catalog, use it, and report this.
- [ ] 2.5 Implement the command in `src/cli.ts` with `parseArgs` from `node:util`: `wishem start <folder> [--port <number>]`, the default port 4747, the terminal lines of the "Examples" section of `design.md`, exit code 1 with the problems for a start that fails, a usage message with a non-zero exit code when no folder is given, and exit code 0 after an interrupt signal. Verify with tests that run the built or source command as a child process: a correct start prints the address; a model that is not correct exits with code 1 and names the file; no folder exits with a non-zero code; an interrupt signal exits with code 0.
- [ ] 2.6 Write `README.md` in ASD-STE100 Simplified Technical English: the command, the two HTTP paths with a `curl` example for each, the layout of a model folder, and what the command does with a problem. Verify that `pnpm lint --filter @thrashplay/wishem-host-nodejs` and `pnpm test --filter @thrashplay/wishem-host-nodejs` pass.
