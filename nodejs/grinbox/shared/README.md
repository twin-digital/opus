# @grinbox/shared

The contracts grinbox's daemon (`@grinbox/server`) and browser application
(`@grinbox/web`) both speak. A private workspace package: it is never published,
and both siblings depend on it with `workspace:*`.

## What lives here

Every shape that crosses the API is declared once, in this package, rather than
separately on each side. That is the whole of its job.

| module                                 | what it declares                                                                                |
| -------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `resources`                            | the closed set of resources and the operations each exposes                                     |
| `operators`                            | the operator type keys and the configuration shape of each built-in type                        |
| `contract`                             | an operator's declared inputs, outputs, and resource operations, derived from its configuration |
| `enums`                                | the closed vocabularies the state schema CHECK-constrains, and the ones deliberately left open  |
| `match-expression`, `match-vocabulary` | the rule language and the reader that evaluates it                                              |
| `template-placeholder`, `body-usage`   | the placeholder grammar, and what reading it implies about fetching a body                      |
| `limits`                               | a limit's shape, and the caps grinbox seeds on install                                          |
| `notifications`                        | a notification kind's name, and the per-kind cooldown setting                                   |
| `money-display`                        | the display form of a stored money value: `19503:USD` renders as `$195.03`                      |
| `models`                               | the closed set of models a user may pick                                                        |
| `api-error`                            | the structured form a refused write answers in                                                  |
| `health`                               | the liveness payload                                                                            |
| `resource-op-result`                   | the outcome a metered resource operation returns                                                |
| `account-display`                      | the icon and colour vocabularies for an account badge                                           |

The daemon owns everything behavioural: the database row types, the operator
implementations, the code version, the metered clients, and the routes. The
browser application declares no wire shape at all — it is typed from the
daemon's own route definitions, which compose the shapes above.

## Using it

One entry point. Import by name from the package root:

```ts
import { contractFromConfig, operatorConfigSchemas, type OperatorTypeKey } from '@grinbox/shared'

const config = operatorConfigSchemas.llm_tagger.parse(body)
const contract = contractFromConfig('llm_tagger', config)
```

Schemas are [zod](https://zod.dev) v4. Each one exports its inferred type
alongside it — `limitDefinitionSchema` and `LimitDefinition`, and so on.

Because the workspace resolves the `source` export condition, a consumer needs
no build of this package: TypeScript and the bundlers read `src/` directly.

## Adding a shape

- A vocabulary the state schema CHECK-constrains goes in `enums.ts`, and its
  members get a closedness test in `schema-invariants.test.ts` — that test fails
  when a closed enum arrives without one.
- A new resource operation goes in `RESOURCE_OPERATIONS` and nowhere else; the
  schemas, the types, and the per-resource validation all derive from it.
- A new operator type needs a `type_key`, a configuration schema, an entry in
  `operatorTypeRegistry`, and its static resource declarations. The invariant
  tests assert those four stay in step.

```
pnpm test        # vitest
pnpm typecheck
pnpm lint
pnpm build
```
