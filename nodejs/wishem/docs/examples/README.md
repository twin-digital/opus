# Examples

> Blueprint, not a specification. See `../README.md` for the status labels.

This folder holds examples. An example shows what Wishem is for. It is not a rule, a requirement, or a design.

- `interactions.md`: worked examples of a designer and the agent, in one room.
- `editor-after-whistle-request.html`: a wireframe of what the designer sees after one of those examples.

## How to use an example

- Use an example to understand what a designer expects.
- Do not build from an example as if it were a specification. The words of a request, the names of the things, and the layout of the wireframe are illustrations.
- If an example disagrees with `../rules.md` or `../concepts.md`, that file is correct and the example is wrong. Correct the example.

## What comes from the owner

In `interactions.md`, the requests of the designer and the "What the designer expects" lists come from the owner. The "What Wishem needs" lists are the reading of the agent that wrote the file.

The wireframe is a sketch from the brainstorm. The owner did not review its details.
