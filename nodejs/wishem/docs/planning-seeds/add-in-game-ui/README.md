# In-game user interface

> Planning seed, not a specification. It collects what the blueprint knows about this topic, as the start of its brainstorm. The folder name is the expected name of the OpenSpec change. See `../../README.md` for the status labels.

## Goal

This topic is the user interface that a player sees in a game: menus, dialog boxes, and the display of health and items. It is not on the roadmap.

## What is agreed

- A toolkit for the tools of the designer is part of the base. See [Tools](../add-designer-tools/README.md).
- A renderer can draw the parts of an in-game user interface with no help from Wishem.

## Open questions

1. **Is a toolkit for in-game user interface part of the base?** The owner is not sure.
2. **Does the agent need a toolkit at a higher level than the renderer to make an in-game user interface?** The first game can show the answer.
